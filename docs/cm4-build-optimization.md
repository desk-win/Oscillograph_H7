# CM4 必须开优化编译（触发扫描的 655 µs 预算）

> 记录人：调试于 2026-09-25 定案。
> 结论已固化进 `CM4/CMakeLists.txt`，从这里改不会再退回去。
> 相关：`CM7/CMakeLists.txt` 里 CM7 的同类覆盖（`-Og`）。

---

## 一句话

CM4 的 `OSC_CH_Poll()` 必须在**半个帧周期（655.36 µs）**内跑完。`-O0` 编译下这条预算超了 4 倍，
表现为**屏幕上波形一直在跳、没有一列是固定的**——看起来像触发/相位对齐的 bug，
实际跟触发逻辑毫无关系。修法是在 `CM4/CMakeLists.txt` 里覆盖 Debug 的优化标志。

---

## 1. 症状，以及它为什么骗人

| 观察到的 | 实际是 |
|---|---|
| 屏幕上没有哪一列是固定的 | 环上 76% 是空洞，一屏窗口跨 5 个环槽位，八成像素是 1.34 秒前的陈旧数据 |
| 去掉输入信号后，屏幕上还有零星波形 | 同上，残影 |
| 换触发边沿 / 调触发电平都没用 | 因为问题不在触发 |

**误导性在于**：环是"CM4 写、CM7 读"的，空洞让**空间上的相邻**变成**时间上的不相邻**，
于是任何"数据是对的"的假设都不成立。人在这个状态下会去查触发逻辑、查窗口计算，
而真正的病根在编译器命令行里。

---

## 2. 根因

`CM4/build/CMakeCache.txt` 里 `CMAKE_BUILD_TYPE=Debug`，而 **`CM4/CMakeLists.txt` 缺少
CM7 那边早就有的 Debug 标志覆盖**（见 `CM7/CMakeLists.txt:44-45`）。

CMake 工具链文件给 Debug 的默认值是 `-O0 -g`，于是整个 CM4 工程（46 个源文件）全部在 `-O0` 下编译。

---

## 3. 证据（都可复现）

### 3.1 编译命令

```bash
grep -o '\-O[0-9sg]' CM4/build/compile_commands.json | sort | uniq -c
# 修复前：  46 -O0
# 修复后：  46 -O2
```

> **注意**：不要去看 `CMakeCache.txt` 里的 `CMAKE_C_FLAGS_DEBUG`——它显示的是**工具链文件写的原始值**
> （`-g`），而我们在 `CMakeLists.txt` 里 `set()` 的覆盖发生在 configure 阶段、写在 cache 之后。
> **唯一可信的依据是 `compile_commands.json`。**

### 3.2 反汇编指令数

半帧 = 2048 个 word，CH1 每个 word 两个样本、CH2 每个 word 一个样本。

| | `-O0`（实测） | `-O2`（实测，最快路径） |
|---|---|---|
| `trig_scan_ch1` 循环体 | **191 条 / word** | **35 条 / word** |
| `trig_scan_ch2` 循环体 | **135 条 / word** | **52 条 / word** |
| 合计（两路同开） | 2048×191 + 2048×135 = **667,648 条** | 2048×35 + 2048×52 = **178,176 条** |
| 240 MHz 下粗估 | **≈ 2.8 ms**，超预算 **4.3 倍** | **≈ 0.74 ms**（见第 8 节的保留意见） |

`-O0` 的 66.8 万条是一次**与输入无关**的固定开销：每条 `if` 都被完整展开成"取数→比较→分支"，
没有合并、没有条件执行。

### 3.3 为什么这套代码特别依赖优化

`oscillograph.c` 里的触发扫描是刻意这么写的：

```c
osc_trig_t loc = *t;                 /* 状态先拷进局部变量 */
for (...) { trig_feed(&loc, v); }    /* trig_feed 是 always_inline */
t->win_min = loc.win_min;            /* 扫完写回 */
t->win_max = loc.win_max;
t->armed   = loc.armed;
```

配套的还有 `trig_feed` 上的 `__attribute__((always_inline))`。**这一整套设计的前提是编译器能把
`loc` 的字段提进寄存器跨整个循环复用**：

- `-O2` 下成立：`win_min` / `win_max` / `armed` / `pos` 全在寄存器里（`r1` / `lr` / `r2` / `r8`），
  循环里一次访存都没有
- `-O0` 下**完全不成立**：`&loc` 老老实实躺在栈上，每取一个字段都要先把它读回来再写回去，
  设计想要省掉的访存一次都省不掉

所以 `-O0` 不是"慢一点"，是把这段代码的**核心优化意图整个作废**。反过来说：**这段代码的正确性能
依赖优化等级，所以构建配置是它的一部分，必须写进构建脚本而不是某台机器的 cache。**

### 3.4 运行时后果的量化

CM4 每落后一次就丢一个半帧（记进 `diag_miss`）。丢掉的半帧对应的环槽位永远不会被写，
**那里的数据是一整圈之前（1.342 s 前）的**。`-O0` 下 CM7 每 4.3 个环槽位才填满 1 个，
所以 76% 的环是空洞。一屏 8192 word 跨 5 个槽位，于是屏幕上大部分内容是 1.3 秒前的。

## 4. 修法

`CM4/CMakeLists.txt`，**位置有硬性要求**：必须在 `project()` 之后、`add_executable()` 之前。

```cmake
set(CMAKE_C_FLAGS_DEBUG "-O2 -g3")
```

- **必须在 `project()` 之后**：工具链文件在那时才设自己的值
- **必须在 `add_executable()` 之前**：否则子目录会在设置生效前把它们拷走
- CM7 那边同理，见 `CM7/CMakeLists.txt:44-45`

**为什么用 `-O2` 而不是 CM7 那边的 `-Og`**：本文档 3.2 节的指令数分析本来就是按 `-O2` 做的。
`-g3` 保留完整调试信息。

**当初担心的"`-O2` 会重排缓冲区"已经不存在**：共享缓冲的三个地址由链接脚本写死
（见 `stm32h747xx_flash_CM4.ld` 里的 `.osc_ch1_buf` / `.osc_ch2_buf` / `.osc_ctrl`）。
可以用符号表确认它们确实钉在原处：

```bash
arm-none-eabi-nm --print-size --size-sort CM4/build/Oscillograph_H7_CM4.elf | grep osc_
# 30034000 00002000 B osc_ch2_buf     ← 0x30034000, 8 KB
# 30030000 00004000 B osc_ch1_buf     ← 0x30030000, 16 KB
```

## 5. 踩过的坑：改缓存会被 reconfigure 冲掉

**上一轮的修法是在 `CM4/build/CMakeCache.txt` 里手改成 `RelWithDebInfo`。**
这个补丁在 2026-09-25 的一次重新 configure 之后**被静默冲掉**（`CMakeCache.txt` 又是 `Debug`），
bug 完整复现。

手改 build 目录里的缓存属于**未纳入版本控制的、一次性的**修改。只要有人重新 configure
（改 CMakeLists、切 IDE、删 build 目录重建），它就没了，而且**不会有任何提示**。

**所以修法必须写在 `CMakeLists.txt` 里**——它是唯一跟着代码走的地方。

## 6. 怎么自查

```bash
# 1. 唯一可信的优化标志检查（应为 46 -O2，不应出现 -O0）
grep -o '\-O[0-9sg]' CM4/build/compile_commands.json | sort | uniq -c

# 2. 反汇编确认状态确实在寄存器里（不应看到循环里有 ldr/str 在反复读写同一个栈地址）
OD="<toolchain>/bin/arm-none-eabi-objdump"
$OD -d --disassemble=osc_scan_half CM4/build/Oscillograph_H7_CM4.elf | less

# 3. 地址契约（三个共享缓冲必须钉在原处）
<toolchain>/bin/arm-none-eabi-nm --print-size CM4/build/Oscillograph_H7_CM4.elf | grep osc_
```

`-O2` 下 `trig_scan_ch1` / `trig_scan_ch2` / `trig_feed` **不再作为独立符号存在**——
它们被内联进了 `osc_scan_half`（`0x08108a74`，1128 字节，约 423 条指令）。
反汇编时要按 `osc_scan_half` 找，不要按 `trig_scan_*` 找。

**`-O0` 的循环特征**（用来确认 bug 复现了）：

- `trig_scan_ch1` / `trig_scan_ch2` 是**独立函数**，被调用
- 循环体里能看到反复从同一个栈偏移 `ldr` 回 `win_min` / `win_max` / `armed`

## 7. 验收判据

**首选（有实测数据支撑）**：CM4 串口的 `miss=` 停止上涨；CM7 探针的 `chN missed` 停止上涨。

2026-09-25 实测（**仅开 CH1**）：

```
[osc] dt=1005000 irq=1526.4/s cmiss=0 | ch1=<与 seq1 完全相等>/0/0 ch2=0/0/0
[OSC] seq1=18683 miss=0 ...
```

CM4 发布到 `seq1=18683` 停住，CM7 也正好搬到 `18683` 停住——**每发布一个半帧就搬一个，
一个不落**；`miss` / `missed` / `overrun` 三个数全程为 0。

**顺带确认了一个前提**：`seq1` 每秒精确涨 **1526**（逐次差值都是 1526，一次不差）。
理论值 2048 word ÷ 320 ns = 1526.04/s。**所以"2048 word × 320 ns = 655.36 µs"这个时基假设是对的**，
ADC 多重交替的 word 周期没有算错。

### 不要用的判据

**`rate1` / `rate2` 不要用。** `rate_update()` 的公式分母是"相邻两次调用"的周期数（= 1 个半帧），
却按 16 次调用（`RATE_AVG_HALVES`）来除，**打出来的数恒是真实值的 16 倍**。

> 该公式已于 2026-09-25 修正（改成累加 16 个半帧的总周期再除）。
> **修正后的正确期望值**：CH1 ≈ 6.25e6 Sa/s，CH2 ≈ 3.125e6 Sa/s。
> 如果还看到 ≈1e8，说明修正没生效。

## 8. 当前余量，以及一个**未验证项**

内存占用（`-O2`，2026-09-25）：FLASH 51612 B (4.92%)、RAM 10680 B (5.43%)、RAM_D2 24672 B (25.10%)。
`-O2` 让代码变大，但 FLASH 才用 5%，无所谓。

**但是：上面第 7 节的实测是"CH2 关着"测的**，只覆盖了 6144 个迟滞比较里的 4096 个（67% 的负载）。
两路同开能不能撑住 655 µs，**目前没有验证过**。

按第 3.2 节的静态下界粗算：

```
CH1 单路:  2048 × 35        =  71,680 条  ≈ 0.30 ms   ← 有余量，与实测 miss=0 吻合
两路同开:  2048 × 35 + 2048 × 52 = 178,176 条 ≈ 0.74 ms   ← 超过 655 µs
```

**所以要补一次两路同开的实测。** 如果 `miss` 开始涨，说明 `-O2` 只解决了单路的情况。

> **重要修正**：本文档早期版本、以及调试过程中曾说过"CM4 的扫描代价与输入信号无关，
> 所以可以空载测吞吐"。**这句话在 `-O2` 下是错的。**
> 反汇编显示编译器把循环拆成了"最快路径 + 一批越界分支块"：常见的分支走向走 35 条，
> 其余情况 `b` 到循环外的块里。**所以实际开销是数据相关的**——信号的形状决定走哪条路径。
> 空载测出的 `miss` 只能当作下界的下界，不能替代带信号实测。

## 9. 如果还不够：下一个杠杆

把每样本的 `edge` 三元式提到循环外。

`trig_feed()` 里 `t->edge` 在**一次扫描过程中是不变的**（`trig_sync()` 每个半帧才更新一次），
但它出现在每个样本的判断里：

```c
if (t->edge == 0u ? (v <= t->arm) : (v >= t->arm)) t->armed = 1u;
```

**`-O2` 没有把它 unswitch 掉**——反汇编里循环体内仍然有 `cmp r3, #0` / `bne`（`r3` = `edge`），
而且更糟：编译器把这个三元式物化成了一个寄存器再测一次：
`ite cc` / `movcc r6, #0` / `movcs r6, #1` / `cbz r6`（4 条，比原来的 `it` + 比较还多）。

正确的做法是拆成两个循环（`edge == 0` 一个、`edge == 1` 一个），或者把 `edge` 变成
两个函数指针/两种 `armed`/`level` 阈值编码方式。这属于"手写 unswitch"。

## 10. 记一笔：这次调试的终点不在软件

同一轮排查的最后结论：**`-O2` 修好之后波形"固定"了但仍有两三种相位在变换，
最终定位到模拟前端**（AD8066 运放 + CD74HC4051 多路开关）。

决定性实验：**跳过运放和多路开关，把信号直接灌进 ADC 引脚 → 相位完全固定住。**

这说明触发、锁存、窗口选择、搬运整条软件链路是通的。剩下的问题在模拟侧，而软件这边
暴露出的是**不够鲁棒**，不是错：

- `cfg_trig_hyst = 16`（[`oscillograph.c:65`](../CM4/Mylibrary/Src/oscillograph.c)）是**绝对计数**，
  不是信号幅度的比例；换一套前端（信号被衰减、噪声抬高）就失效
- 这个值**运行时没有任何人在改**——`ctrl_defaults()` 开机写一次 16，`trig_sync()` 读它，
  CM7 一行都没有。设计上它归 CM7 写，但界面从来没暴露过
- 自适应电平在"一直在触发"时永不重算（`trig_update()` 的 `no_trig >= OSC_NO_TRIG_WINS` 条件），
  于是 `level` 会冻结在开机后头 10.5 ms 那一个统计窗口的值上

最后这一节只是**记录范围**，不是本文档的主题——本文档只管构建配置。
前端那条线要另开一份。
